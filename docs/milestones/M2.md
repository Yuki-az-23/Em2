Key behaviours proven by integration tests:

- **ADR-011 uniform publish:** an ordinary message and a twelve-copy spam flood with a false claim get
  byte-identical responses apart from the id, both after the pad.
- **Claims never become state:** a body that fences `joy/yellow`, sent by a `surprised/aqua` sender,
  is shown as `surprised/aqua`; the claim is stored for the dossier only.
- **Dossier:** ten copies with a false claim reach risk ≥ 0.6 and drift 1. Other principals get the same
  404 as unknown content until they hold the observer role.
- **Idempotency:** the same key replays the same id with `Idempotent-Replayed: true`. The same key with a
  different body is a 409. Keys are per principal.
- **Media:** wrong magic bytes give 400, SVG gives 415, more than 5 MB gives 413. Downloads are served
  with `nosniff`.
- **One-connection pool:** listing messages (a cross-module call inside an open transaction) completes;
  with the nested-scope code disabled the same test hangs until the suite times out (mutation check).

## Found and fixed during M2

- **Deadlock risk (design):** provider services opened a second connection while the caller held one,
  and the outbox dispatcher did the same for every subscriber. Under load both could exhaust the pool.
  Fixed by ADR-012 (shared transaction with `SET LOCAL ROLE`, subscribers under savepoints).
- The static schema-reference check misread event names (`identity.principal.deleted`) as table
  references; it now tells three-segment event names from two-segment table names.

## Differences from the blueprint

- Bridges live in a minimal `ledger` module from M2 instead of a stub inside ingest (ADR-012).
- `ingest.messages` is not partitioned yet; partitioning and retention arrive with the journal in M6.
- Media upload takes the raw image as the request body (no multipart), which is simpler for agents.
- Messages of a deleted principal stay, shown with author "deleted"; erasure of content is an M6
  retention decision.
