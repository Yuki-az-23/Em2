Key behaviours proven by tests:

- **Per-receiver verdicts:** for one message, a fitting receiver gets `pass` with score 0.75, a far one
  `defer` with score 0, a receiver who blocked the sender gets nothing, a receiver without a bridge
  gets `pass` without a score, and the author is never a receiver.
- **Release:** a deferred message reaches the feed with `released_at` after the receiver changes bridge,
  after the receiver turns the filter off, and after the message itself transitions.
- **Pressure:** one reply never moves a message; the same actor replying again is capped; the author
  and actors without a `pass` exchange add nothing; the third distinct reply moves `joy/yellow` to
  `trust/lime`, the transition is listed without the trigger's identity, `GET /v1/messages/{id}`
  shows the new state, and the pressure endpoint shows counts to receivers only (404 to the author
  and to outsiders). Brace adds 0.5 and unbrace removes exactly that; both are idempotent.
- **Flood:** the tenth copy of a promotion reaches a fitting receiver as `shape` with risk ≥ 0.6, the
  first as `pass`; all ten sender responses are byte-identical apart from the id.
- **Shadow mode:** a deferred and a denied message are delivered with their real kind and `shadow: true`.
- **Ingress:** responses for a delivered request, a deferred request and an unknown handle are
  byte-identical apart from the id, padded, without banners. The upstream receives the original
  bytes with `EM2-Verdict`, `EM2-Score`, `EM2-Message-Id`, `EM2-Sender` and `EM2-Rule-Version` and
  without the caller's credentials. Its answer arrives in the caller's feed as a reply without the
  upstream's `Server` and `X-Powered-By`. A deferred request reaches its upstream only after release.
  An upstream 500 with a stack trace never reaches the caller; the internal record keeps it.
  The exchange ends in `responded`.
- **Egress:** a page is stored as text with scripts removed, shaped, without a state; the upstream
  sees no credentials and no EM2 user agent. With the guard on, loopback, `localhost`,
  `169.254.169.254`, `[::1]`, `10.0.0.1` and `0x7f000001` are refused, and an ingress upstream on
  loopback is not dialed.
- **Mutation check:** with the defer branch of the decision table disabled, four verdict
  integration tests fail.

## Found and fixed during M3

- Two test packages migrating different databases on one server raced on `CREATE ROLE` (roles are
  server-wide; the migration lock is per database). Role creation now tolerates the duplicate.
- A first ingress draft stored the message before the request row in separate transactions, so the
  verdict could deliver the request before its body existed and it would never be forwarded. The
  request row and the message are now written in one transaction.
- The public OpenAPI hygiene test banned `score` and `threshold` everywhere, which would also have
  hidden a receiver's own verdict from them. It now checks every operation and allows those fields only
  on the listed receiver-owned ones.

## Differences from the blueprint

- **Ingress is asynchronous and senders never see deny** (ADR-013). B1 and B12 described a synchronous
  forward and a `403` for deny.
- **The score compares the receiver's bridge with the message's current state**, which starts at the
  sender's stance and moves by pressure (ADR-013), so transitions change who receives a message.
- Settings, blocks and the ingress upstream live in `ledger` from M3 instead of M4.
- `shape` does not rate-limit per sender and receiver yet (M4, with quotas).
- Agents with the `bridge:write` scope may change their own settings and blocks; there is no separate
  settings scope, so `core.AgentScopes` did not change.
- Pressure decays in whole hours, so interactions within the same hour add up exactly.
- Ingress accepts JSON, plain text and Markdown bodies on one path, `POST /ingress/{handle}`, not
  arbitrary sub-paths and methods; A2A and MCP upstream protocols follow with the MCP adapter.
